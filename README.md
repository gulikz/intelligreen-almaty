# IntelliGreen Almaty — геопортал (прототип)

Интеллектуальная геопространственная система поддержки принятия решений по управлению зелёной
инфраструктурой города Алматы. Демонстрация к заявке на грантовый проект акимата города Алматы, 2026.
Приоритетное направление — комфортная городская среда.

**Геопортал:** https://gulikz.github.io/intelligreen-almaty/
**Открытый API:** https://gulikz.github.io/intelligreen-almaty/api.html

Полноценный веб-ГИС: подложки (тёмная, светлая, OpenStreetMap, спутник, рельеф), десять тематических
слоёв, оверлеи, фильтр-запрос, идентификация, измерение расстояний, поиск, атрибутивная таблица
с сортировкой и выгрузкой в CSV и GeoJSON.

## Что здесь показано

Сервис проходит методику проекта целиком, а не изображает её:

1. **Сетка кварталов.** Город покрыт гексагональной сеткой 350 м — 2 365 кварталов. В рабочей системе это
   сетка H3 разрешения 9 примерно на 30 000 ячеек; здесь взят представительный срез.
2. **Слияние источников.** 23 признака на квартал: восемь из гражданских отчётов (число обращений,
   средняя и максимальная серьёзность, накопленное доверие, доля верифицированных, число уникальных
   участников, доля поведенческих категорий) и пятнадцать из открытых геоданных (NDVI и его тренд за три
   года, температура поверхности, плотность населения и застройки, дорожная сеть, водонепроницаемость,
   рельеф, тип землепользования).
3. **Предиктивная модель.** XGBoost, обученный на этих признаках, выгружен в JSON и **выполняется прямо
   в браузере**. Добавьте гражданский отчёт — VGI-признаки квартала пересчитаются, и модель немедленно
   выдаст новый EcoRisk. Это и есть замкнутый цикл из методики, работающий вживую.
4. **Пространственная статистика.** Локальная статистика Getis-Ord Gi* по кольцу из шести соседей,
   двусторонние p-значения с поправкой Бенджамини–Хохберга на множественность проверок, глобальный
   индекс Морана. Всё считается в браузере на актуальных прогнозах.
5. **Приоритизация.** Многокритериальная свёртка: риск деградации, дефицит зелени, плотность населения,
   плотность обращений — сто приоритетных кварталов с рекомендуемым действием.
6. **Порог по цене ошибки.** Пропустить деградированный квартал втрое дороже ложной тревоги, поэтому
   порог выбирается минимизацией `3·FN + FP`, а не по умолчанию 0,5. Ползунок показывает, чем
   приходится платить за каждое смещение порога.

## Честность оценки

Метрики получены **пространственной кросс-валидацией**: город разбит на 12 блоков методом k-средних
по координатам, модель проверяется на блоке, которого не видела при обучении. Без этого соседние
кварталы попадают и в обучение, и в проверку, и точность оказывается завышенной.

| Показатель | Значение |
|---|---|
| R² прогноза EcoRisk | 0,897 |
| Средняя абсолютная ошибка | 0,480 |
| AUC детекции высокого риска | 0,988 |
| Пропуск деградации (FNR) при пороге по цене ошибки | 6,6 % |
| Ложная тревога (FPR) | 4,0 % |

Данные — синтетический эко-двойник Алматы: истинный EcoRisk известен по построению, поэтому ошибку
прогноза можно показать честно, сравнив с эталоном прямо в карточке квартала. В рабочей системе те же
признаки приходят из Sentinel-2, Landsat, OpenStreetMap, открытого кадастра, WorldPop и SRTM.

## Ограничение демонстрации

Приём гражданских отчётов работает **только в браузере посетителя**: отчёт меняет признаки квартала и
модель пересчитывает прогноз на месте, но на сервер ничего не уходит и другим посетителям не видно.
Статический хостинг для общего хранилища непригоден по определению. В рабочей системе этот слой —
PostgreSQL с PostGIS, FastAPI, очередь верификации, ограничение частоты и оценка доверия участника.

## Структура

```
index.html        геопортал: карта Leaflet, панель слоёв, фильтр, карточка объекта, таблица
portal.js         инференс модели, Getis-Ord Gi*, индекс Морана, MCDA, слои, инструменты, экспорт
portal.css        оформление портала
api.html          документация открытого API с примерами для Python и QGIS
style.css         оформление страницы API
data/hexes.json   2 365 кварталов: координаты, 23 признака, эталон, out-of-fold прогнозы
data/model.json   деревья XGBoost в компактном виде для браузера
data/meta.json    районы, землепользование, соседи для Gi*, метрики, категории
data/layers.json  12 тепловых карт по категориям обращений и кластеры «синдромов»
api/v1/           статический read-only API: GeoJSON кварталов, районы, приоритеты, метрики
build/            скрипты сборки данных, модели и слоёв + исходные таблицы
```

## Возможности портала

**Подложки.** Тёмная и светлая Esri Canvas, OpenStreetMap, спутник Esri World Imagery, рельеф OpenTopoMap.

**Тематические слои.** EcoRisk (прогноз модели), горячие зоны Gi*, синдромы проблем, плотность
обращений, двенадцать тепловых карт по категориям обращений, NDVI, температура поверхности,
плотность застройки, плотность населения, рельеф. Непрозрачность регулируется.

**Оверлеи.** Границы и названия восьми районов (получены растворением гексагональной сетки),
ТОП-100 приоритетных адресов с рангом, собственные гражданские отчёты.

**Фильтр-запрос.** Диапазон EcoRisk, район, землепользование, только значимые горячие зоны,
только высокий риск по модели. Результат подсвечивается на карте и попадает в таблицу и выгрузку.

**Инструменты.** Идентификация, добавление гражданского отчёта, измерение расстояний,
поиск по кварталу, району и координатам, переход к полному экстенту.

**Атрибутивная таблица.** Десять полей, сортировка по любому столбцу, связь с картой,
выгрузка выборки в CSV и GeoJSON.

**Панель объекта.** Все признаки квартала по слоям A–F, прогноз модели и его отклонение от эталона,
локальная статистика Gi*, структура обращений по категориям, рекомендуемый тип работ.

**Аналитика.** Рейтинг районов, глобальный индекс Морана, число значимых горячих зон,
метрики модели, синдромы проблем.

**Мой вклад.** Геймификация из методики: эко-баллы, уровни участия, выгрузка своих отчётов.

## Воспроизведение

```bash
pip install numpy pandas scikit-learn scipy xgboost
cd build
python3 07_build_service.py    # переобучает модель, пересобирает data/ и api/
python3 08_build_layers.py     # тепловые карты по категориям и кластеры синдромов
```

Скрипт сверяет выгруженные деревья с самим XGBoost и падает, если расхождение превышает 1e-4.
Сравнение признака с порогом идёт в `float32`: в двойной точности маршрут по дереву иногда расходится
с обучающим кодом, и прогноз уезжает на десятые доли.
